## 1. 招募渠道与优先顺序

| 优先级 | 渠道 | 动作 | 预期 |
|--------|------|------|------|
| **P0** | 熟人微信 1v1 + 体验群 | 列出 30–50 个「家有父母/关心饮食」的人 → 私聊邀请 → 拉 1 个 8–20 人体验群 | 主来源，目标 8–12 有效样本 |
| **P1** | 小红书「子女向」短内容 | 发 3–5 条「帮父母看懂配料表」笔记，评论区约试用 → 加微信/进群 | 降熟人偏差，补 2–5 人 |
| P2 | 同事/同学群一次广播 | 群公告 + 自愿私聊，不刷屏 | 补充 |
| 不做 | 医院/药店 BD、信息流买量、个人小程序支付获客 | — | #35 验证期否决 |

**合格对象（有效样本，对齐 #28 S1）**

- 角色：**子女**（30–50 岁优先；家中有慢病或高龄父母更佳）
- 设备：**对方自己的手机**，非你代操作全程
- 完成：打开链接 →（同意）→ **至少尝试填档案** → 上传一张配料表图 → 看到结果
- 访谈：结束后 5–10 分钟问答，有记录

**不合格（可体验但不计入 8 人）**

- 仅你自己反复测
- 全程你拿着手机代点
- 未出识别结果就离开
- 纯好奇点开、拒绝任何问答

## 2. 邀约话术（微信 1v1）

```
嗨，我在做一个小工具的用户验证，想请你帮个忙（大约 15 分钟）。

场景：很多子女想帮父母看食品包装上的配料/添加剂，但字小又难懂。
工具：手机打开网页，拍一下配料表，会结合你填的父母健康情况，
给出「需要特别留意」的参考提示，还能语音读出来。
注意：只是科普参考，不是医生建议，也不能替代就医。

如果你方便：
1）用你自己的手机打开链接：（贴公开链接）
2）按页面走一遍（可填父母大概的慢病/用药，没有可跳过）
3）结束后我语音/文字问你几句真实感受

完全自愿，数据仅用于我改进产品，不会公开你的个人信息。
这周或下周哪个晚上方便？
```

## 3. 试用任务脚本（用户自己手机，约 8–12 分钟）

请引导对方**按顺序**：

| 步 | 任务 | 你观察/记录 |
|----|------|-------------|
| 0 | 用自己手机打开公开链接（非你的电脑投屏代操作） | 是否打得开、加载是否过慢 |
| 1 | 完成法律同意（若出现） | 是否读、是否卡 |
| 2 | 进入健康档案：尽量填 **父母** 的 1 项慢病或用药（可匿名化描述） | 是否愿填（软证伪信号） |
| 3 | 去扫描页：拍/上传 **真实包装配料表**（家里零食/保健品均可） | 是否会拍、是否模糊放弃 |
| 4 | 等待结果；查看 **识别状态**、**建议下一步** 与 **关注项**（无大号参考分） | 是否理解「参考/核对」而非判决 |
| 5 | 点一次 **听结果**（与屏幕同源） | 是否有声、是否觉得吵/有用 |
| 6 | （可选）「有识别错的配料」排除一项 | 结论是否更新 |
| 7 | （可选）回历史看刚才那条 | 是否找到、是否仍出现「XX 分」主叙事 |

**阻断时你可做（#29 允许）**

- 帮解释「参考不是医嘱」
- 链接挂了 → 修部署/换时间再约  
- **不要**为了演示去开发对比/Pro/新 OCR

## 4. 访谈脚本（试用后 8–12 分钟）

开场：  
「谢谢！没有标准答案，你怎么想就怎么说。我在验证值不值得继续做，不好听的意见更有用。」

| # | 问题 | 对应指标 |
|---|------|----------|
| Q1 | 刚才整体顺不顺？卡在哪一步？ | 可用性 |
| Q2 | 用一句话说，这个工具**对你帮父母有什么用**？（或「没什么用」） | 增量 / 说得清 |
| Q3 | 和你自己看包装、或用过的配料 App 比，**多出来的一点**是什么？没有也可以说没有 | **说得清增量**（#28） |
| Q4 | 健康档案那一步，你愿不愿意填父母的病/用药？为什么？ | 软证伪 |
| Q5 | 结果里的提示，你觉得像「参考信息」还是像「告诉你能不能吃」？ | 合规感知 |
| Q6 | **你会不会再用来帮父母看包装？** 是 / 否 / 不确定（请追问原因） | **再用 B1** |
| Q7 | 假门付费：若以后有个**大约一年 68–99 元**的版本，专门给子女帮父母看配料+档案提示——  
① 不愿付 ② 会考虑给父母/家庭买 ③ 愿意留联系方式进意向名单 | **付费 P1** |
| Q8 | 还有什么让你想关掉、或想推荐给其他子女的？ | 开放 |

**7 日跟进（复扫，B1 行为腿）**

试用后第 5–7 天发一条：  
「还在验证，不打扰。若你这周又帮父母扫过一次包装，回我『扫了』；没扫回『没有』也行。」

## 5. 记录模板（一人一行）

复制到表格 /飞书 / Excel。字段与 #28 闸门对齐。

| 字段 | 说明 |
|------|------|
| id | S01, S02… |
| date | 试用日期 |
| channel | 微信熟人 / 体验群 / 小红书 / 其他 |
| relation | 强熟人 / 弱熟人 / 陌生 |
| role | 子女 / 配对子女 / 老人 / 配对老人 |
| device_own | 是/否（对方自己手机） |
| path_complete | 是/否（上传→出结果） |
| archive_filled | 是/否/跳过 |
| voice_ok | 是/否/跳过 |
| **recognition_honesty** | 完整 / 部分 / 无法确认 / 未观察 |
| **saw_action_line** | 是否看到「建议下一步」 |
| **correction_tried** | 是否试过排除错误配料 |
| reuse_verbal | 是/否/未知（Q6） |
| reuse_rescan_7d | 是/否/未知（7 日） |
| reuse_count | 再用记 1（口头是 **或** 复扫是） |
| delta_clear | 是/否（Q3 说得清增量） |
| pay_tier | 1 / 2 / 3（Q7） |
| pay_signal | 是/否（2 或 3 为是） |
| **gate_incident** | 是/否（人身风险误信 / P0 回退等 → 停扩招） |
| soft_fail_notes | 拒档案 / 百度就够 / 其他 |
| blocker_notes | 卡点（勿写「已告知能吃」类执行备注） |
| quote | 一句原话（用户原话可保留口语） |
| valid_sample | 是/否（子女计入 #28 的 ≥8） |
| **wave** | 招募波次 wave1… |

**闸门速算（有效样本 ≥8 后）**

- 再用率 = sum(reuse_count) / 有效样本数  
- 付费人数 = pay_signal 为是的人数  
- 说得清人数 = delta_clear 为是的人数  
- 对照 #28 判 Go / Pivot / Stop

空表文件：`research/validation-sample-log.csv`

## 6. 人工执行 Checklist（待你完成）

### 本周启动（第 1 周）

- [ ] 确认公开链接在自己手机上 L2 路径可走通（同意→档案→扫→结果→语音）
- [ ] 列出 30–50 个可邀请名单（备注：是否有父母慢病）
- [ ] 发出至少 **15** 条 1v1 邀请
- [ ] 建体验群（可选）并置顶链接 + 免责一句
- [ ] 复制 `validation-sample-log.csv` 开始记人

### 第 2–4 周

- [ ] 累计 **有效样本 ≥8**（目标 12）
- [ ] 每人做完访谈 Q1–Q8 并写入表
- [ ] 第 5–7 天跟进复扫
- [ ] 若链接阻断：只修 Bug/部署，不新做功能（#29）

### 第 4–6 周收口

- [ ] 有效样本仍 &lt;8 → 判定 **证据不足**，继续招，不 Go/Stop
- [ ] ≥8 → 按 #28 计算再用率、付费人数、增量清晰度 → 书面记 Go / Pivot / Stop
- [ ] 把汇总表路径评论到 #26 或新开结果票

### 明确不由本 Agent 代劳

- 代你加微信、代发小红书、代做访谈（需你本人出面建立信任）

## 7. 合规提醒（#32，访谈与文案）

- 对外与访谈中避免：「保证能吃/不能吃」「代替医生」「停药」  
- 推荐：「参考提示」「需留意」「以包装和医嘱为准」  
- 健康信息尽量最小必要；记录表避免写父母真名+完整病历
