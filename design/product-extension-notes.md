# 产品延展备忘（非当前 V1 范围）

## 宠物粮 / 宠物零食版（用户构想）

**结论：可以做成「子品牌 / 第二模式」，不要直接混进当前人类配料 V1。**

| 维度 | 人类版（拍了就懂） | 宠物版（示意） |
|------|-------------------|----------------|
| 知识源 | GB2760、食品添加剂风险表 | 宠物毒理学清单（木糖醇、巧克力/可可、葡萄干、洋葱大蒜、部分人工甜味剂等）+ 饲粮标签规范 |
| 用户话术 | 给家人偶尔吃/少买 | 猫/狗能否接触、是否误食风险 |
| 合规 | 非医疗 | 非兽医诊断；误食应急引导「联系宠物医院」 |
| OCR 目标 | 配料表 | 配料 + 保证分析值（粗蛋白/脂肪）可选 |
| 技术复用 | 拍照→OCR→结构化→卡片→TTS | **流水线可复用**；匹配库与评分规则必须分叉 |

### 建议形态

1. **同一 App 内「模式切换」**：人用 / 猫 / 狗（不要一页混算）。  
2. **独立知识包** `data/pet_hazards.*`，与 GB2760 SQLite **隔离**。  
3. **MVP 范围**：只做「高危成分红绿灯 + 语音」，不做全营养配方优化。  
4. **时机**：人类版验证通过（访谈/复购意向）后再开；否则分心。

### 命名示意

- 拍了就懂 · 家人  
- 拍了就懂 · 萌宠（或独立名，避免老人误进宠物模式）

## 其他高价值延展（按性价比）

1. **给谁吃 chip**（孩子/老人/自己）— 只改排序与提示，不改库。  
2. **微信分享图** — 一句话 + 分数，获客。  
3. **超市场景** — 历史对比「上次买的更省心」。  
4. **B 端** — 社区团购/养老驿站大字平板（仍是 Web）。

当前工程已实现的结果页方向：**一句话结论 → 听结果 → 需留意添加剂优先**，与延展无关，应先把这条路径打磨到访谈可用。
